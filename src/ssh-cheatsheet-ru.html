Шпаргалка по SSH

Подключение и ключи, файл настроек клиента, проброс портов и переход через промежуточный узел, копирование файлов, агент и переадресация, настройка сервера, разбор проблем.

Подключение

ssh user@host
Обычное подключение на порт 22
ssh -p 2222 user@host
Другой порт
ssh -i ~/.ssh/id_work user@host
Конкретный закрытый ключ
ssh user@host "uptime; df -h"
Выполнить команду и выйти
ssh -t user@host "sudo journalctl -f"
Выделить терминал — нужно для интерактивных команд
ssh -v / -vvv
Подробный вывод: первый шаг при разборе отказов
ssh -o StrictHostKeyChecking=accept-new user@host
Принять ключ нового узла без вопроса

Ключи

ssh-keygen -t ed25519 -C "комментарий"
Создать пару ключей; ed25519 — современный выбор
ssh-keygen -t rsa -b 4096
RSA, если требуется совместимость со старым сервером
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@host
Положить открытый ключ в ~/.ssh/authorized_keys на сервере
ssh-keygen -p -f ~/.ssh/id_ed25519
Сменить пароль на ключе
ssh-keygen -l -f ключ.pub
Отпечаток ключа — для сверки
ssh-keygen -R host
Убрать запись узла из known_hosts после переустановки сервера

Права важны: ~/.ssh — 700, закрытый ключ — 600, authorized_keys — 600. При более широких правах SSH откажется работать.

Файл настроек клиента

# ~/.ssh/config
Host prod
    HostName 10.0.0.5
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_prod
    ServerAliveInterval 60

Host *.internal
    ProxyJump bastion

Host bastion
    HostName bastion.example.com
    User admin

Host *
    AddKeysToAgent yes
    HashKnownHosts yes

После этого достаточно ssh prod. Настройки действуют и для scp, rsync, git.

Промежуточный узел

ssh -J bastion user@internal
Переход через бастион одной командой
ProxyJump bastion
То же в файле настроек
ssh -A user@host
Переадресация агента: ключи остаются на вашей машине

Переадресацию агента включайте только на доверенные узлы: администратор такого сервера может воспользоваться вашим агентом, пока вы подключены. ProxyJump безопаснее.

Проброс портов

ssh -L 5432:localhost:5432 user@host
Локальный проброс: порт удалённой базы доступен у вас как localhost:5432
ssh -L 8080:internal-web:80 user@bastion
Доступ к узлу внутренней сети через бастион
ssh -R 9000:localhost:3000 user@host
Обратный проброс: ваш локальный сервис виден на удалённой машине
ssh -D 1080 user@host
SOCKS-прокси: браузер ходит через удалённый узел
ssh -fN -L ...
В фоне и без запуска оболочки — только туннель

Копирование файлов

scp file user@host:/path/
Загрузить файл
scp user@host:/path/file .
Скачать
scp -r каталог user@host:/path/
Каталог целиком
rsync -avz --progress src/ user@host:/dst/
Лучше для больших объёмов: докачивает и показывает ход
sftp user@host
Интерактивная передача: get, put, ls
ssh user@host "tar -czf - /data" > data.tar.gz
Архивирование на лету, без временных файлов на сервере

Долгие сеансы

ServerAliveInterval 60 / ServerAliveCountMax 3
Не давать соединению отвалиться по тайм-ауту
ControlMaster auto, ControlPath ~/.ssh/cm-%r@%h:%p, ControlPersist 10m
Повторное использование соединения: следующие подключения открываются мгновенно
tmux или screen на сервере
Работа переживёт обрыв связи
mosh
Альтернативный клиент для нестабильной сети

Настройка сервера

Файл /etc/ssh/sshd_config, после правки — sshd -t для проверки и systemctl reload sshd.

PermitRootLogin no
Запретить вход под root
PasswordAuthentication no
Только по ключам — главная мера против перебора
PubkeyAuthentication yes
Вход по ключу
AllowUsers deploy admin
Белый список учётных записей
Port 2222
Смена порта уменьшает шум в журналах, но не заменяет защиту
MaxAuthTries 3, LoginGraceTime 30
Ограничение попыток и времени на вход
AllowTcpForwarding no
Запрет туннелей, если они не нужны

Перед перезапуском службы оставьте открытым второй сеанс: ошибка в настройках иначе закроет доступ насовсем.

Разбор проблем

  • Permission denied (publickey) — сервер не принял ключ: проверьте права на файлы, нужный ключ в -i и содержимое authorized_keys.
  • Connection refused — служба не слушает порт или мешает межсетевой экран; ss -ltnp на сервере.
  • Connection timed out — пакеты не доходят: маршрут, группы безопасности, VPN.
  • Host key verification failed — ключ узла изменился; если сервер переустанавливали, уберите запись ssh-keygen -R, иначе разберитесь, почему.
  • Too many authentication failures — агент перебирает все ключи; помогает IdentitiesOnly yes с явным IdentityFile.
  • Журнал сервера: journalctl -u ssh -n 50 — там видно причину отказа.
