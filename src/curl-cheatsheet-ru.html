Шпаргалка по cURL

Запросы к API и сайтам из командной строки: методы и данные, заголовки и аутентификация, загрузка файлов, куки, прокси и TLS, измерение времени, отладка.

Основное

curl https://example.com
Вывести тело ответа
curl -I URL
Только заголовки (запрос HEAD)
curl -i URL
Заголовки вместе с телом
curl -v URL
Подробный ход запроса: соединение, TLS, заголовки
curl -s URL
Без индикатора загрузки; -sS — тихо, но с ошибками
curl -L URL
Следовать перенаправлениям
curl -o file.zip URL / -O
Сохранить в файл; с именем из URL
curl -f URL
Вернуть ненулевой код при ответе 4xx и 5xx — важно в сценариях

Методы и данные

curl -X POST URL
Явный метод (при -d POST подставляется сам)
curl -d '{"a":1}' -H "Content-Type: application/json" URL
Тело в формате JSON
curl -d @body.json URL
Тело из файла
curl -d "user=ann&id=7" URL
Данные формы
curl --json '{"a":1}' URL
Короткая запись: ставит и заголовки, и тело (curl 7.82+)
curl -X DELETE URL
Удаление
curl -G -d "q=поиск" -d "page=2" URL
Собрать строку запроса для GET
curl --data-urlencode "q=текст с пробелами" URL
Кодирование значения

Заголовки и доступ

-H "Authorization: Bearer $TOKEN"
Маркер доступа
-H "Accept: application/json"
Желаемый формат ответа
-u user:password
Базовая аутентификация (пароль лучше вводить по запросу: -u user)
-H "X-Request-Id: 123"
Произвольный заголовок
-A "MyAgent/1.0" / -e https://ref.example
User-Agent и Referer
--oauth2-bearer $TOKEN
То же, что заголовок Authorization

Секреты в командной строке видны в списке процессов и в истории оболочки. Передавайте их через переменную окружения или -H @файл.

Файлы и куки

curl -F "file=@photo.jpg" -F "title=Фото" URL
Отправка формы с файлом
curl -T file.txt ftp://host/path/
Загрузка методом PUT
curl -C - -O URL
Продолжить прерванную загрузку
curl -c cookies.txt -b cookies.txt URL
Сохранить и отправлять куки — так проходят сценарии со входом
curl --limit-rate 500k URL
Ограничить скорость

Время и повторы

--max-time 30 / --connect-timeout 5
Предел на весь запрос и на установку соединения
--retry 3 --retry-delay 2
Повторы при сетевых сбоях и ответах 5xx
--retry-all-errors
Повторять при любой ошибке
-w "%{http_code} %{time_total}\n" -o /dev/null -s URL
Код ответа и общее время без вывода тела
-w "@format.txt"
Разбор по этапам: time_namelookup, time_connect, time_appconnect, time_starttransfer

TLS, прокси, адреса

--cacert ca.pem / --cert client.pem --key client.key
Свой удостоверяющий центр; клиентский сертификат
-k
Не проверять сертификат — только для отладки, никогда в рабочих сценариях
--resolve example.com:443:10.0.0.5
Подставить адрес, минуя DNS: проверка нового сервера до переключения записи
-x http://proxy:3128 / --proxy-user u:p
Прокси и доступ к нему
--interface eth1
Отправить запрос с конкретного интерфейса
--http2 / --http1.1
Версия протокола

Рецепты

# Проверка доступности в сценарии
if ! curl -fsS --max-time 5 https://api/health > /dev/null; then
    echo "сервис недоступен" >&2
    exit 1
fi

# Красивый JSON
curl -s https://api/users | jq '.[] | {id, name}'

# Замер по этапам
curl -s -o /dev/null -w "dns=%{time_namelookup} tls=%{time_appconnect} ttfb=%{time_starttransfer} total=%{time_total}\n" URL

# Скачать список ссылок
xargs -n1 -P4 curl -sO < urls.txt

# Отправить содержимое файла как JSON
curl -X POST -H "Content-Type: application/json" --data-binary @payload.json URL

Полезно знать

  • В средствах разработчика браузера у запроса есть пункт «Копировать как cURL» — быстрый способ воспроизвести обращение.
  • -f и --max-time обязательны в сценариях: без них молчаливый провал легко пропустить.
  • Одинарные кавычки вокруг JSON защищают его от подстановок оболочки.
  • По умолчанию curl не следует перенаправлениям — отсюда «пустые» ответы 301 и 302.
  • Для повторяемых наборов запросов держите файл с параметрами: curl --config req.txt.
