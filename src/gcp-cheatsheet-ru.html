Шпаргалка по Google Cloud

Устройство проектов и доступов, команды gcloud, вычисления и контейнеры, хранилища и базы данных, сеть, наблюдение и расходы. Ориентирована на разработчика, который выкладывает и сопровождает приложение.

Как устроена платформа

  • Организация → папка → проект — иерархия; ресурсы и счета привязаны к проекту.
  • Регион и зона — где физически работает ресурс; зона входит в регион.
  • IAM — кому что разрешено: участник получает роль на ресурс.
  • Служебный аккаунт — учётная запись для программ, а не для человека.
  • API включаются отдельно в каждом проекте — частая причина ошибки «API not enabled».

gcloud services enable run.googleapis.com

--format=json / --filter="status=RUNNING"
Машинный вывод и фильтрация — работают почти во всех командах

Доступы

gcloud projects add-iam-policy-binding PROJ --member=user:a@b.com --role=roles/viewer
Выдать роль пользователю
gcloud iam service-accounts create app-sa
Создать служебный аккаунт
gcloud iam service-accounts keys create key.json --iam-account=...
Ключ файлом — применяйте только там, где нельзя иначе
gcloud projects get-iam-policy PROJ
Кто какие роли имеет в проекте

Осторожно: роли уровня owner и editor дают слишком много. Берите узкие роли и Workload Identity вместо файлов с ключами.

gcloud compute instances list
Список машин со статусами
gcloud compute ssh vm1 --zone=europe-west1-b
Подключиться по SSH с автоматической настройкой ключей
gcloud compute instances stop / start / delete vm1
Остановка снимает плату за процессор, но не за диск
gcloud compute instance-groups managed create ...
Группа с автоматическим масштабированием и восстановлением

Секреты и настройки

gcloud secrets create db-pass --replication-policy=automatic
Создать секрет
echo -n "пароль" | gcloud secrets versions add db-pass --data-file=-
Добавить версию значения
gcloud secrets versions access latest --secret=db-pass
Прочитать текущее значение
--set-secrets=DB_PASS=db-pass:latest
Подключить секрет к службе Cloud Run переменной окружения

Расходы

  • Бюджеты и оповещения включайте сразу — это защита от неприятных сюрпризов.
  • Метки (--labels=env=prod,team=api) позволяют разделить счёт по командам и средам.
  • Платят не только работающие машины: диски, снимки, внешние адреса и исходящий трафик тоже стоят денег.
  • Долговременные нагрузки дешевле с обязательствами по использованию; пакетные задачи — на вытесняемых машинах.
  • Хранилище: правила жизненного цикла переводят старые объекты в холодные классы автоматически.

Частые ошибки

  • API not enabled — включите нужную службу в этом проекте.
  • PERMISSION_DENIED — не хватает роли у пользователя или служебного аккаунта, под которым работает служба.
  • Команда выполнилась «не там» — проверьте активный проект, регион и зону в gcloud config list.
  • Квоты: часть ограничений региональные; их увеличивают отдельным запросом.
  • Имя корзины Cloud Storage уникально глобально — занятое имя встречается часто.
