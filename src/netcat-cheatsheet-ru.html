Шпаргалка по netcat

Универсальный инструмент для проверки сетевых соединений: доступность портов, простой обмен данными, прослушивание, передача файлов и разбор проблем связи. Применяйте в своих сетях и на своих узлах.

Какая версия

  • ncat (из пакета Nmap) — самая функциональная, поддерживает TLS и списки доступа.
  • netcat-openbsd — типичная в Debian и Ubuntu; ключ -N закрывает соединение после ввода.
  • netcat-traditional — старая версия; часть ключей отличается.
  • Проверить: nc -h в первой строке покажет вариант.

Проверка доступности

nc -zv host 443
Открыт ли порт: без передачи данных, с сообщением о результате
nc -zv host 20-25
Диапазон портов
nc -zvu host 53
UDP-порт (результат менее надёжен, чем для TCP)
nc -zv -w 2 host 5432
С тайм-аутом: не ждать зависшее соединение
nc -v host 80 <<< "HEAD / HTTP/1.0"
Отправить строку и посмотреть ответ

В сценариях удобно опираться на код возврата: nc -z host 443 && echo открыт. Если netcat недоступен, в bash есть </dev/tcp/host/443.

Прослушивание

nc -l -p 9000
Ждать подключение на порту 9000
nc -lk -p 9000
Не завершаться после первого клиента (в ncat и openbsd-версии)
nc -l -p 9000 > received.bin
Принять данные в файл
nc -l -p 9000 < answer.txt
Отдать содержимое файла подключившемуся
ncat -l 9000 --ssl
Прослушивание с TLS
ncat -l 9000 --allow 10.0.0.0/24
Ограничить, кто может подключиться

Передача данных

# Принять файл
nc -l -p 9000 > archive.tar.gz

# Отправить на принимающий узел
nc -N host 9000 < archive.tar.gz

# Каталог целиком через архив на лету
tar -czf - /data | nc -N host 9000
nc -l -p 9000 | tar -xzf - -C /restore

# Быстрый обмен сообщениями между двумя терминалами
nc -l -p 9000          # на одной машине
nc host 9000           # на другой

netcat не шифрует и не проверяет подлинность. Для передачи через недоверенную сеть используйте ncat --ssl, а лучше — ssh, scp или rsync.

Диагностика служб

nc host 25
Поговорить с почтовым сервером вручную: EHLO, MAIL FROM
nc host 6379
Redis: отправить PING и увидеть +PONG
printf "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n" | nc example.com 80
Сырой HTTP-запрос без клиента
nc -l -p 8080
Посмотреть, что именно шлёт ваш клиент или вебхук
nc -u host 514
Отправка в syslog по UDP

Полезные ключи

-l
Режим прослушивания
-p порт
Порт (в некоторых версиях указывается без ключа)
-u
UDP вместо TCP
-z
Только проверка, без передачи данных
-v / -vv
Подробный вывод
-w секунды
Тайм-аут соединения и простоя
-n
Не разрешать имена — быстрее и нагляднее
-N
Закрыть соединение по завершении ввода: без него передача файла «висит»
-s адрес
Отправлять с конкретного локального адреса

Чем заменить

  • ss -ltnp — посмотреть, что слушает порты на своей машине.
  • curl — для HTTP понятнее и удобнее.
  • openssl s_client -connect host:443 — для TLS-служб.
  • socat — более мощный родственник: туннели, преобразование протоколов, юникс-сокеты.
  • ssh -L — безопасный проброс вместо самодельных туннелей.

Замечания

  • Ключи различаются между версиями: если команда ведёт себя не так, начните с nc -h.
  • Проверяйте порты только на своих узлах или по согласованию — это такая же сетевая активность, как сканирование.
  • Открытый nc -l на публичном адресе принимает соединения от кого угодно: ограничивайте адрес и не оставляйте его включённым.
  • Режим запуска команды при подключении (-e) во многих сборках отключён намеренно — не пытайтесь его обойти на чужих системах.
  • Для UDP отсутствие ответа ничего не доказывает: служба может просто молчать.
