Шпаргалка по Wireshark

Анализ сетевого трафика: захват и его ограничение, фильтры отображения, разбор TCP и HTTP, статистика, работа из командной строки через tshark и dumpcap, типовые находки.

Прежде всего

Перехватывайте трафик только в своей сети или там, где это разрешено. Дамп содержит данные пользователей — обращайтесь с файлом захвата как с чувствительными сведениями и удаляйте, когда он больше не нужен.

Удобства интерфейса

  • Ctrl+F — поиск по содержимому пакетов; ищите по строке, шестнадцатеричному коду или фильтру.
  • Ctrl+M — пометить пакет, чтобы вернуться к нему позже.
  • Правая кнопка → Apply as Filter — быстро построить фильтр из выбранного поля.
  • View → Time Display Format → Seconds Since Previous Displayed Packet — удобно измерять паузы.
  • Analyze → Expert Information — сводка замечаний: потери, дубликаты, ошибки контрольных сумм.
  • Цветовые правила настраиваются: свои цвета для интересных условий экономят время.

Командная строка

tshark -D
Список интерфейсов
tshark -i eth0 -f "port 443" -w cap.pcapng
Захват с фильтром в файл
tshark -r cap.pcapng -Y "http.response.code >= 500"
Чтение файла с фильтром отображения
tshark -r cap.pcapng -T fields -e ip.src -e ip.dst -e tcp.port
Выбрать поля — удобно для дальнейшей обработки
tshark -r cap.pcapng -q -z conv,tcp
Статистика соединений без вывода пакетов
dumpcap -i eth0 -b filesize:100000 -b files:10 -w cap.pcapng
Долгий захват с кольцевым буфером: легче Wireshark и надёжнее
editcap -A "2026-01-01 10:00:00" in.pcapng out.pcapng
Вырезать нужный отрезок времени
mergecap -w all.pcapng a.pcapng b.pcapng
Объединить файлы захвата

Захват на сервере

# Записать на удалённой машине, смотреть локально
ssh user@host "sudo tcpdump -i any -U -s0 -w - 'port 80'" | wireshark -k -i -

# Ограниченный по времени и объёму захват
sudo timeout 60 tcpdump -i any -w /tmp/cap.pcap -C 50 -W 4 'host 10.0.0.5'

На сервере обычно ставят tcpdump, а разбирают дамп уже в Wireshark на своей машине — графический интерфейс на рабочем узле не нужен.

Что искать

  • Повторные передачи и дубликаты ACK — потери в сети или перегрузка.
  • Нулевое окно (TCP ZeroWindow) — получатель не успевает обрабатывать данные.
  • RST сразу после SYN — служба не слушает порт или соединение сбрасывает межсетевой экран.
  • SYN без ответа — пакеты не доходят: маршрут или фильтрация.
  • Долгая пауза перед ответом — время тратит приложение, а не сеть.
  • Медленные запросы DNS — частая причина «тормозов», которые списывают на приложение.
  • Ошибки TLS — несовпадение версий, имени в сертификате или отсутствие доверия к центру.
