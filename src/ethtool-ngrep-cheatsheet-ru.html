Шпаргалка по ethtool и ngrep

Две утилиты для разных уровней диагностики: ethtool показывает состояние сетевой карты и канала, ngrep ищет текст в проходящем трафике. Работайте только на своих узлах.

ethtool: состояние канала

ethtool eth0
Скорость, режим дуплекса, наличие несущей (Link detected)
ethtool -i eth0
Драйвер, версия прошивки, шина
ethtool -S eth0
Счётчики: ошибки, отброшенные пакеты, переполнения
ethtool -g eth0
Размеры кольцевых буферов приёма и передачи
ethtool -k eth0
Аппаратные разгрузки: контрольные суммы, сегментация
ethtool -c eth0
Параметры объединения прерываний
ethtool -l eth0
Число очередей
ethtool -p eth0 10
Помигать индикатором порта 10 секунд — найти нужный разъём в стойке

ethtool: изменение настроек

ethtool -s eth0 speed 1000 duplex full autoneg off
Зафиксировать скорость и режим
ethtool -G eth0 rx 4096 tx 4096
Увеличить буферы при потерях на приёме
ethtool -K eth0 gro off tso off
Отключить разгрузки — иногда нужно при отладке или в виртуальных средах
ethtool -C eth0 rx-usecs 50
Настроить объединение прерываний: меньше нагрузка, выше задержка
ethtool -L eth0 combined 8
Число очередей под число ядер

Изменения через ethtool не переживают перезагрузку. Закрепляйте их в настройках сети дистрибутива или в юните systemd, иначе после ребута всё вернётся.

На что смотреть в счётчиках

  • rx_errors, rx_crc_errors — испорченные кадры: кабель, разъём, оптика.
  • rx_dropped, rx_no_buffer — не успели принять: маленькие буферы или перегруженный процессор.
  • tx_errors, collisions — проблемы передачи; коллизии в современных сетях сигнализируют о несогласованном дуплексе.
  • Link detected: no — физически нет связи: кабель, порт коммутатора, питание модуля.
  • Скорость 100 Мбит/с там, где ожидается гигабит, — почти всегда кабель или автосогласование.
  • Сравнивайте счётчики в динамике: watch -n1 'ethtool -S eth0 | grep -i err'.

Соседние инструменты

ip -s link show eth0
Статистика интерфейса без ethtool
ip a / ip r
Адреса и маршруты
mii-tool eth0
Старый вариант проверки канала
iperf3 -c host
Измерить реальную пропускную способность
mtr host
Потери и задержки по всему маршруту

ngrep: поиск в трафике

ngrep -d any "GET" port 80
Пакеты со строкой на всех интерфейсах
ngrep -d eth0 -q "пароль"
Тихий режим: только совпадения
ngrep -W byline "HTTP" port 8080
Вывод с переносами строк — читаемо для текстовых протоколов
ngrep -i "user-agent" port 80
Без учёта регистра
ngrep -x "" port 5432
Шестнадцатеричный дамп для двоичных протоколов
ngrep -O dump.pcap "" port 80
Записать совпавшее в файл для разбора в Wireshark
ngrep -I dump.pcap "ошибка"
Искать в уже записанном файле
ngrep -t / -T
Метки времени: абсолютные и относительно предыдущего пакета

Фильтры и примеры

# Запросы к конкретному хосту
ngrep -d any -W byline "" "host 10.0.0.5 and port 80"

# Запросы DNS по имени
ngrep -d any -q "example" udp port 53

# Тело POST-запросов к API
ngrep -d any -W byline "POST /api" port 8080

# Кто шлёт незашифрованные пароли в форме
ngrep -d any -i "password=" port 80

Синтаксис фильтра после шаблона — тот же BPF, что у tcpdump: host, net, port, and, or, not.

Ограничения ngrep

  • Видит только незашифрованный трафик: в HTTPS ничего полезного не найдёт.
  • Ищет по отдельным пакетам — строка, разорванная между пакетами, не совпадёт. Для сборки потока нужен Wireshark.
  • Требует прав root и заметно нагружает узел на большом трафике — сужайте фильтр.
  • Дамп содержит пользовательские данные: обращайтесь с ним как с чувствительной информацией.
  • Для серьёзного разбора привычнее tcpdump для записи и Wireshark для анализа.

Порядок разбора сетевой проблемы

  1. Физика: ethtool eth0 — есть ли канал и та ли скорость.
  2. Ошибки на интерфейсе: ethtool -S и ip -s link.
  3. Адреса и маршруты: ip a, ip r, доступность шлюза.
  4. Имена: dig — не в DNS ли дело.
  5. Порт и путь: nc -zv, mtr.
  6. Содержимое: ngrep или tcpdump с последующим разбором в Wireshark.
