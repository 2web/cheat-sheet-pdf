Шпаргалка по Ansible

Инвентарь, разовые команды, плейбуки, переменные и роли, шаблоны и секреты, отладка. Ansible работает по SSH и не требует агента на управляемых узлах.

Инвентарь

Список узлов и групп. Формат INI или YAML, файл по умолчанию — /etc/ansible/hosts, обычно же его кладут рядом с плейбуками.

[web]
web1.example.com
web2.example.com ansible_port=2222

[db]
db1.example.com

[prod:children]
web
db

[all:vars]
ansible_user=deploy
ansible-inventory -i hosts --list
Показать разобранный инвентарь со всеми переменными
ansible-inventory -i hosts --graph
Дерево групп и узлов

Разовые команды

ansible all -i hosts -m ping
Проверить связь и вход по SSH на всех узлах
ansible web -a "uptime"
Выполнить команду на группе (модуль command по умолчанию)
ansible all -m shell -a "df -h | tail -5"
Модуль shell — когда нужны конвейеры и перенаправления
ansible db -m ansible.builtin.service -a "name=postgresql state=restarted" -b
Перезапуск службы с повышением прав (-b — become)
ansible all -m setup -a "filter=ansible_distribution*"
Собрать факты об узлах и отфильтровать нужные

Запуск плейбуков

ansible-playbook -i hosts site.yml
Обычный запуск
--check
Пробный прогон: показать, что изменится, ничего не меняя
--diff
Показать построчную разницу изменяемых файлов
--limit web1.example.com
Ограничить выполнение узлом или группой
--tags deploy / --skip-tags slow
Выполнить или пропустить помеченные задачи
--start-at-task "Установка пакетов"
Начать с конкретной задачи
-e "version=1.4.2"
Передать переменную; такие значения перекрывают все остальные
-K / -k
Спросить пароль sudo; спросить пароль SSH

Плейбук

- name: Настройка веб-серверов
  hosts: web
  become: true
  vars:
    app_port: 8080
  tasks:
    - name: Установить nginx
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Положить конфигурацию
      ansible.builtin.template:
        src: site.conf.j2
        dest: /etc/nginx/conf.d/site.conf
        mode: "0644"
      notify: Перезагрузить nginx

    - name: Служба запущена и включена
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

  handlers:
    - name: Перезагрузить nginx
      ansible.builtin.service:
        name: nginx
        state: reloaded

Частые модули

package / apt / dnf
Установка пакетов; package не зависит от дистрибутива
copy / template
Скопировать файл; второй прогоняет его через шаблонизатор Jinja2
file
Каталоги, права, владелец, символьные ссылки, удаление
lineinfile / blockinfile
Правка строки или блока в существующем файле
user / group
Учётные записи и группы
git
Выкачать репозиторий на узел
uri
HTTP-запрос: проверки работоспособности и вызовы API
command / shell
Произвольная команда; для shell доступны конвейеры и переменные оболочки

Переменные и факты

group_vars/<группа>.yml, host_vars/<узел>.yml
Переменные групп и отдельных узлов — основной способ хранения настроек
{{ переменная }}
Подстановка в задачах и шаблонах
{{ ansible_facts['distribution'] }}
Факты, собранные с узла: система, адреса, память, диски
register: result
Сохранить результат задачи, затем result.stdout, result.rc
when: ansible_facts['os_family'] == "Debian"
Условное выполнение
loop: [nginx, curl, htop]
Повтор задачи для каждого элемента (item)
| default("значение")
Значение по умолчанию, если переменная не задана

Приоритет (от слабого к сильному): роли → inventory → group_vars → host_vars → переменные плейбука → -e в командной строке.

Роли

Роль — стандартная раскладка каталогов, которую можно повторно использовать и выкладывать в Galaxy.

roles/webserver/
├── tasks/main.yml
├── handlers/main.yml
├── templates/site.conf.j2
├── files/
├── vars/main.yml
├── defaults/main.yml
└── meta/main.yml
ansible-galaxy init roles/webserver
Создать заготовку роли
ansible-galaxy install -r requirements.yml
Установить сторонние роли и коллекции
roles: [webserver]
Подключение роли в плейбуке

defaults/ — значения, которые предполагается переопределять; vars/ — те, что менять не нужно.

Секреты: Ansible Vault

ansible-vault create secrets.yml
Создать зашифрованный файл
ansible-vault edit secrets.yml
Редактировать с расшифровкой на лету
ansible-vault encrypt_string "пароль" --name db_password
Зашифровать одно значение для вставки в обычный YAML
ansible-playbook site.yml --ask-vault-pass
Спросить пароль при запуске
--vault-password-file ~/.vault_pass
Взять пароль из файла — удобно в CI

Проверка и отладка

ansible-lint site.yml
Проверка стиля и типичных ошибок
ansible-playbook --syntax-check site.yml
Только разбор синтаксиса
-v / -vvv
Подробный вывод; три уровня показывают и команды SSH
ansible.builtin.debug: var=result
Вывести значение переменной по ходу выполнения
ansible.builtin.assert: that: ...
Остановить выполнение, если условие не выполнено
ANSIBLE_STDOUT_CALLBACK=yaml
Читаемый многострочный вывод результатов

Полезно помнить

  • Идемпотентность — повторный запуск не должен ничего менять. Модули это обеспечивают, command и shell — нет, им помогают creates= и changed_when.
  • Handlers выполняются один раз в конце игры и только если задача что-то изменила.
  • ansible.cfg в каталоге проекта задаёт инвентарь, пользователя и параметры SSH — меньше ключей в командной строке.
  • Полные имена модулей (ansible.builtin.copy) устойчивее коротких, особенно при использовании коллекций.
