Выход

Базы, схемы, таблицы

CREATE DATABASE shop;
CREATE SCHEMA app;

CREATE TABLE app.users (
    id         bigserial PRIMARY KEY,
    email      text NOT NULL UNIQUE,
    name       text,
    balance    numeric(12,2) DEFAULT 0,
    is_active  boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE app.users ADD COLUMN phone text;
ALTER TABLE app.users RENAME COLUMN name TO full_name;
DROP TABLE app.users;

Для денег берите numeric, а не float. Для времени — timestamptz: он хранит момент с учётом часового пояса.

Типы данных

  • Числа: smallint, integer, bigint, numeric(p,s), double precision.
  • Строки: text (обычный выбор), varchar(n), char(n).
  • Дата и время: date, time, timestamptz, interval.
  • Логический: boolean.
  • Структуры: jsonb, массивы (text[]), hstore.
  • Прочее: uuid, inet, tsvector для полнотекстового поиска.

Запросы

SELECT id, email
FROM app.users
WHERE is_active AND created_at >= now() - interval '30 days'
ORDER BY created_at DESC
LIMIT 20 OFFSET 0;

INSERT INTO app.users (email, full_name)
VALUES ('a@b.com', 'Аня')
ON CONFLICT (email) DO UPDATE
    SET full_name = EXCLUDED.full_name
RETURNING id;

UPDATE app.users SET balance = balance + 100 WHERE id = 1;
DELETE FROM app.users WHERE is_active = false;
RETURNING

Соединения и группировка

INNER JOIN
Только совпавшие строки обеих таблиц
LEFT JOIN
Все строки левой; отсутствующие справа станут NULL
FULL JOIN / CROSS JOIN
Обе стороны целиком; все пары строк
GROUP BY … HAVING
Агрегация и фильтр по результату агрегации
count(*), sum(), avg(), min(), max()
Основные агрегатные функции
string_agg(name, ', ')
Склеить значения группы в строку
DISTINCT ON (user_id) …
По одной строке на группу — особенность PostgreSQL
SELECT u.id,
       count(o.id) AS orders,
       sum(o.total) AS revenue
FROM app.users u
LEFT JOIN app.orders o ON o.user_id = u.id
GROUP BY u.id
HAVING count(o.id) > 0
ORDER BY revenue DESC NULLS LAST;

Оконные функции и CTE

WITH recent AS (
    SELECT * FROM app.orders
    WHERE created_at > now() - interval '7 days'
)
SELECT user_id,
       total,
       row_number() OVER (PARTITION BY user_id ORDER BY total DESC) AS rn,
       sum(total)   OVER (PARTITION BY user_id) AS user_total
FROM recent;

Оконные функции считают по группе, не схлопывая строки. Полезны row_number, rank, lag, lead, нарастающие суммы.

Индексы

CREATE INDEX ON app.users (email);
Обычный индекс B-дерева
CREATE UNIQUE INDEX ...
Уникальность значения
CREATE INDEX CONCURRENTLY ...
Построение без блокировки записи — так делают на рабочей базе
CREATE INDEX ON t (a, b);
Составной: порядок столбцов важен, работает для условий по префиксу
CREATE INDEX ON t (lower(email));
По выражению — если ищете по нему же
CREATE INDEX ON t USING gin (doc jsonb_path_ops);
GIN для jsonb, массивов и полнотекстового поиска
CREATE INDEX ON t (id) WHERE is_active;
Частичный индекс: меньше и быстрее

Индексы ускоряют чтение и замедляют запись. Неиспользуемые находите через pg_stat_user_indexes и удаляйте.
