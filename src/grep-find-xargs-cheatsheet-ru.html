Шпаргалка по grep, find и xargs

Три утилиты, которые чаще всего работают вместе: grep ищет по содержимому, find — по свойствам файлов, xargs превращает найденное в аргументы команд.

grep: основное

grep "текст" файл
Строки с совпадением
grep -i
Без учёта регистра
grep -n
С номерами строк
grep -v
Наоборот: строки без совпадения
grep -c
Только количество совпадений
grep -l / -L
Имена файлов, где есть совпадение; где его нет
grep -w / -x
Совпадение целым словом; строкой целиком
grep -o
Вывести только совпавшую часть
grep -q
Молча: важен только код возврата, удобно в условиях

grep: поиск по дереву

grep -rn "шаблон" /etc
Рекурсивно с номерами строк
grep -rn --include="*.py" "def " .
Только в файлах по маске
grep -rn --exclude-dir={.git,node_modules} "TODO" .
Пропустить каталоги
grep -A3 -B2 "ошибка" app.log
Три строки после и две до совпадения (-C2 — по две с обеих сторон)
grep -E "ошибка|сбой|отказ"
Расширенные выражения: альтернативы, +, {n,m}
grep -F "строка.с.точками"
Искать как обычный текст, без регулярных выражений
grep -P "\d{3}-\d{2}"
Синтаксис PCRE, если grep собран с его поддержкой
zgrep "шаблон" app.log.gz
Поиск прямо в сжатых журналах

find: где искать и что

find /var/log -name "*.log"
По имени (-iname — без учёта регистра)
find . -type f / -type d / -type l
Только файлы, каталоги или ссылки
find . -maxdepth 2
Ограничить глубину обхода
find . -path "*/test/*" -prune -o -print
Пропустить ветку дерева
find . -xdev
Не выходить за пределы одной файловой системы
find . -empty
Пустые файлы и каталоги

find: отбор

-size +100M / -size -1k
Больше и меньше указанного
-mtime -7 / -mtime +30
Изменён за последнюю неделю; старше месяца
-mmin -60
Изменён за последний час
-newer файл
Новее указанного файла
-user deploy / -group www-data
По владельцу и группе
-perm -u+w / -perm 600
По правам доступа
\( -name "*.log" -o -name "*.tmp" \)
Объединение условий: -o — или, по умолчанию — и
! -name "*.gz"
Отрицание

find: что делать с найденным

-print / -print0
Вывести путь; через нулевой байт — безопасно для имён с пробелами
-delete
Удалить найденное. Сначала посмотрите список без этого ключа
-exec команда {} \;
Запуск для каждого файла отдельно
-exec команда {} +
Пакетами: заметно быстрее
-execdir команда {} \;
Запуск в каталоге файла — надёжнее при странных именах
-ls
Подробный список, как ls -l

xargs

... | xargs команда
Превратить строки ввода в аргументы
-0
Ввод разделён нулевыми байтами — пара к find -print0
-n 1
По одному аргументу на запуск
-P 4
Четыре процесса параллельно
-I {}
Подставить аргумент в нужное место: xargs -I {} mv {} /dst/
-r
Не запускать команду при пустом вводе
-p / -t
Спрашивать подтверждение; печатать команду перед запуском
-d '\n'
Свой разделитель

Связки

# Найти и упаковать старые журналы
find /var/log -name "*.log" -mtime +7 -print0 |
    xargs -0 -P4 gzip

# Заменить строку во всех файлах проекта
grep -rl "старый_домен" --include="*.conf" . |
    xargs sed -i 's/старый_домен/новый_домен/g'

# Удалить пустые каталоги снизу вверх
find . -type d -empty -delete

# Кто занимает место: топ-20 файлов
find / -xdev -type f -printf '%s %p\n' 2>/dev/null |
    sort -rn | head -20

# Поиск текста только в изменённых за сутки файлах
find . -type f -mtime -1 -print0 |
    xargs -0 grep -n "ошибка"

# Посчитать строки кода без учёта служебных каталогов
find . -name "*.py" -not -path "*/.venv/*" -print0 |
    xargs -0 wc -l | tail -1

Что помнить

  • Имена с пробелами и переводами строк ломают простые конвейеры: связка -print0 и xargs -0 — привычка по умолчанию.
  • Любую команду с -delete или rm сначала выполните без них и просмотрите список.
  • -exec … + быстрее, чем \;: меньше запусков процесса.
  • Для больших репозиториев ripgrep (rg) быстрее grep и сам пропускает игнорируемое git.
  • Порядок условий в find влияет на скорость: сперва дешёвые проверки (-type f, -name), затем дорогие.
