Шпаргалка по cron и rsync

Две основы регулярного обслуживания: cron запускает задачи по расписанию, rsync переносит и синхронизирует файлы. Плюс таймеры systemd как современная замена cron.

cron: формат строки

┌── минута (0–59)
│ ┌── час (0–23)
│ │ ┌── день месяца (1–31)
│ │ │ ┌── месяц (1–12)
│ │ │ │ ┌── день недели (0–7, 0 и 7 — вс)
│ │ │ │ │
* * * * *  команда
*/15 * * * *
Каждые 15 минут
0 3 * * *
Ежедневно в 03:00
0 3 * * 1
По понедельникам в 03:00
30 2 1 * *
Первого числа каждого месяца в 02:30
0 9-18 * * 1-5
Каждый час с 9 до 18 по будням
@reboot / @daily / @weekly
Сокращения: при загрузке, ежедневно, еженедельно

cron: управление

crontab -e / -l / -r
Редактировать, показать, удалить задания пользователя
crontab -u deploy -l
Задания другого пользователя (нужны права)
/etc/crontab, /etc/cron.d/*
Системные задания: в них есть дополнительное поле — имя пользователя
/etc/cron.daily/
Каталоги для сценариев без указания времени
journalctl -u cron / grep CRON /var/log/syslog
Проверить, запускалось ли задание

cron: подводные камни

  • Окружение бедное: PATH короткий, профиль оболочки не читается. Пишите полные пути или задавайте PATH в начале crontab.
  • Вывод уходит в почту, которой обычно нет. Перенаправляйте: >> /var/log/job.log 2>&1.
  • Знак % в команде имеет особое значение — экранируйте как \%.
  • Расписание в часовом поясе системы; при переходе на летнее время задания около двух ночи ведут себя странно.
  • Долгие задания могут наложиться друг на друга — оборачивайте в flock -n /tmp/job.lock команда.
  • Задание молча не работает — проверьте права на скрипт и наличие строки запуска в журнале.
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=""

*/10 * * * * flock -n /tmp/sync.lock /opt/app/sync.sh >> /var/log/sync.log 2>&1

Таймеры systemd

# /etc/systemd/system/backup.service
[Service]
Type=oneshot
ExecStart=/opt/scripts/backup.sh

# /etc/systemd/system/backup.timer
[Timer]
OnCalendar=*-*-* 03:00:00
RandomizedDelaySec=300
Persistent=true

[Install]
WantedBy=timers.target
systemctl enable --now backup.timer
Включить таймер
systemctl list-timers
Когда что запускалось и запустится
journalctl -u backup.service
Вывод задания — собирается автоматически, перенаправлять не нужно
Persistent=true
Выполнить пропущенный запуск после включения машины

rsync: основное

rsync -av src/ dst/
Копирование с сохранением прав, времени и ссылок
rsync -avz src/ user@host:/dst/
Через SSH со сжатием
rsync -av --dry-run src/ dst/
Показать, что произойдёт, ничего не меняя
rsync -av --progress больших_файлов/ dst/
Показывать ход передачи
rsync -av --delete src/ dst/
Удалить в приёмнике то, чего нет в источнике
rsync -av -e "ssh -p 2222" src/ user@host:/dst/
Нестандартный порт SSH

Косая черта решает всё: src/ копирует содержимое каталога, src — сам каталог внутрь приёмника. Ошибка приводит к лишней вложенности или к записи не туда.

rsync: отбор файлов

--exclude '*.log' --exclude 'node_modules'
Исключить по маске
--exclude-from=.rsyncignore
Список исключений файлом
--include '*.conf' --exclude '*'
Взять только нужное: порядок правил важен
--max-size=100M / --min-size=1k
Ограничения по размеру
--files-from=list.txt
Передать только перечисленные пути

rsync: полезные ключи

-a
Архивный режим: -rlptgoD — рекурсия, ссылки, права, время, владелец, группа
-z / --compress-level=9
Сжатие в канале
-P
То же, что --partial --progress: докачка прерванного
--bwlimit=5000
Ограничить скорость, КБ/с
--checksum
Сравнивать по контрольной сумме, а не по размеру и времени — медленнее, но надёжнее
--backup --backup-dir=/backup/$(date +%F)
Сохранять заменяемые файлы
--link-dest=/backup/prev
Инкрементные копии: неизменённые файлы связываются жёсткой ссылкой и не занимают места
--numeric-ids
Не преобразовывать идентификаторы владельцев — для переноса между системами

Рецепты

# Выкладка сайта: удалить лишнее, не трогать загрузки пользователей
rsync -avz --delete --exclude 'uploads/' ./dist/ user@host:/var/www/site/

# Ежедневная инкрементная копия
rsync -a --delete --link-dest=/backup/latest /data/ /backup/$(date +%F)/
ln -sfn /backup/$(date +%F) /backup/latest

# Перенос каталога между серверами через бастион
rsync -avz -e "ssh -J bastion" /data/ user@internal:/data/

# Проверка перед опасной синхронизацией
rsync -avn --delete src/ dst/ | head -50

Что помнить

  • Любую команду с --delete сначала запускайте с -n: это единственная защита от потери данных.
  • rsync передаёт только изменившиеся части файлов — поэтому он выигрывает у scp на повторных запусках.
  • Права и владельцы сохраняются только при достаточных правах на приёмнике; иначе используйте --no-owner --no-group.
  • Для регулярной синхронизации по расписанию сочетайте cron (или таймер systemd), flock и запись вывода в журнал.
  • Копия считается рабочей только после пробного восстановления — проверяйте её регулярно.
